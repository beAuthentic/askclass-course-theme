# 01. 모듈 리스트와 핵심 요구사항

우선순위 정의
- **P0**: 4주 공개 베타에 포함. 고객이 가입해서 스스로 가치를 확인할 수 있는 최소 집합.
- **P1**: 베타 이후 5~12주. 운영 단계 셀프 업데이트와 실제 매출 발생 구조.
- **P2**: 3개월 이후. 엔터프라이즈 요구와 Knowledge Studio 완전 연동.

"MVP 깊이" 표기
- **기능**: 실제 사용 가능한 수준으로 구현
- **데모**: 샘플 도메인에서만 동작해도 됨. 오류 처리·엣지케이스 최소화

## 공통 요구사항 (모든 모듈에 적용)

### 사용성·디자인 원칙 "쉽지만 가볍지 않게"
1. **3단 레이아웃**: 좌측 내비게이션(워크스페이스·온톨로지 트리), 중앙 작업 영역(그래프 캔버스 또는 표), 우측 컨텍스트 패널(선택 항목 상세·품질·ROI 기여).
2. **점진적 노출**: 기본 화면은 비전문가가 이해할 수 있는 언어(예: "개념", "관계", "규칙"). 모든 화면에서 한 번의 클릭으로 **전문가 서랍(Expert drawer)** 이 열려 원본 SPARQL/Turtle/OWL을 보고 편집할 수 있음.
3. **가치 스트립(Value strip)**: 앱 상단에 이번 달 누적 효익(원), 질의 수, 절감 시간이 항상 표시. ROI 계산기(M07)의 실측값과 연결.
4. **가르치는 빈 상태**: 데이터가 없는 화면은 "무엇을 하면 되는지"를 3단계로 안내하고 샘플 도메인으로 즉시 채울 수 있는 버튼 제공.
5. **밀도**: 엔터프라이즈 사용자를 위해 정보 밀도는 높게, 여백과 타이포그래피로 정돈. 보라색 그라데이션, 과도한 카드 그림자 등 흔한 "AI 제품" 스타일 금지.
6. **키보드 우선**: 커맨드 팔레트(⌘K)로 개념 검색·질의·화면 이동. 다크 모드 지원.
7. **디자인 토큰**: 기본색 딥 네이비, 강조색 1개(그래프 하이라이트용), 품질 점수용 의미색 3단계. 한글 Pretendard, 영문 Inter, 코드 JetBrains Mono.

### 기술 공통
- 모노레포: `apps/web`(Next.js 15 App Router, TypeScript, Tailwind, shadcn/ui), `apps/api`(FastAPI, SQLAlchemy 2, Pydantic v2), `packages/samples`(샘플 온톨로지·데이터), `packages/contracts`(OpenAPI에서 생성한 TS 타입).
- 모든 API는 테넌트 스코프. 요청마다 `workspace_id` 검증. 테넌트 간 데이터 격리 테스트 필수.
- 모든 LLM 호출은 `LLMGateway` 인터페이스를 통해서만. 프로바이더 교체 가능. 호출마다 토큰·비용·지연시간을 미터링 이벤트로 기록.
- 모든 트리플스토어 접근은 `TripleStoreAdapter` 인터페이스를 통해서만. 베타는 Oxigraph 내장, 이후 Knowledge Studio 어댑터 추가.
- 모든 사용자 노출 문자열은 i18n 키. 하드코딩 금지.
- 테스트: 백엔드 pytest(테넌트 격리·어댑터·ROI 산식), 프론트 Vitest, E2E Playwright(가입→샘플→질의→ROI 흐름 1개).
- 관측: 구조화 로그(JSON), 요청 ID, 에러 트래킹 훅(Sentry 호환).

## P0 모듈 상세

### M01. 테넌트·계정·온보딩
**목적** 회사 이메일로 3분 안에 가입하고 샘플 워크스페이스에 도착한다.

핵심 요구사항
- 이메일 매직 링크 로그인 (비밀번호 없음). 무료 이메일 도메인(gmail, naver, daum, outlook 등 공개 목록 + 관리자 추가) 차단. 차단 시 "회사 이메일로 가입해 주세요" 안내와 영업 문의 링크.
- 같은 이메일 도메인 사용자가 가입하면 기존 조직 참여 제안(자동 합류는 관리자 승인 필요).
- 조직(Organization) → 워크스페이스(Workspace) → 온톨로지(Ontology) 계층. 역할: Owner, Editor, Viewer.
- 온보딩 3단계: (1) 이름·직무·관심 도메인 선택 (2) 샘플 도메인 선택 (3) 첫 질의 실행. 각 단계 이탈률 이벤트 기록.
- 트라이얼 14일. 남은 일수와 한도 사용률을 상단에 표시. 만료 후 읽기 전용.

수용 기준
- 신규 사용자가 가입 완료까지 클릭 5회 이하, 90초 이내 (Playwright 측정).
- 개인 메일 도메인 가입 시도가 차단되고 이벤트가 기록된다.
- 테넌트 A 토큰으로 테넌트 B 리소스에 접근하면 404를 반환한다.

### M02. 샘플 도메인 워크스페이스
**목적** 가입 직후 "이미 동작하는 지식그래프"를 보고 만진다.

핵심 요구사항
- 제조 BOM 도메인 온톨로지(OWL/Turtle): 설비(Equipment), 부품(Part), BOM 구조, 공급업체(Supplier), 고장 이력(FailureEvent), 정비 작업(MaintenanceOrder), 문서(Manual/Spec). 클래스 25~40개, 객체 속성 20개 내외, 데이터 속성 30개 내외, 한/영 레이블과 정의(rdfs:comment) 필수.
- 인스턴스 데이터: 설비 50대, 부품 2,000종, 고장 이력 1,000건, 공급업체 30개, 문서 200건 수준의 합성 데이터. 결정적 시드로 재생성 가능.
- **의도적 결함 5~8개** 포함(레이블 누락, 고아 클래스, 도메인/레인지 누락, 중복 개념, 영문 레이블 누락)으로 M06 품질 리포트가 의미 있는 결과를 보여주도록 함.
- 샘플 질문 12개(한/영): "지난 6개월 고장이 가장 잦은 설비와 그 부품 공급업체는?" 같은 3-hop 이상 질문 포함. 각 질문에 검증된 정답 SPARQL을 함께 저장(NL2SPARQL 평가용 골든셋).
- 워크스페이스 생성 시 20초 이내 로드.

수용 기준
- 샘플 질문 12개 모두 골든 SPARQL로 결과가 나온다.
- 품질 리포트가 의도된 결함을 모두 검출한다.
- 온톨로지 전문가 리뷰 서명(도메인 타당성).

### M03. 트리플스토어 어댑터
**목적** Knowledge Studio API가 미확인인 상태에서도 개발을 진행하고, 확인 후 어댑터만 교체한다.

핵심 요구사항
- 인터페이스 `TripleStoreAdapter`: `query(sparql) -> ResultSet`, `update(sparql)`, `load(graph_iri, turtle)`, `export(graph_iri) -> turtle`, `stats(graph_iri) -> {triples, classes, properties, instances}`, `health()`.
- 구현 1: `OxigraphAdapter` (pyoxigraph 임베디드, 워크스페이스별 named graph, 디스크 영속).
- 구현 2: `SparqlHttpAdapter` (SPARQL 1.1 Protocol 표준. Query/Update 엔드포인트, Basic/Bearer 인증). Knowledge Studio가 표준을 따르면 이것으로 연결.
- 구현 3 스텁: `KnowledgeStudioAdapter` (TODO 표시, 확인해야 할 질문 목록을 docstring으로: 엔드포인트 URL 형식, Update 지원 여부, 인증, named graph 정책, 벌크 로드 API, 버전 관리 API).
- 쿼리 타임아웃(기본 15초), 결과 행 제한(기본 5,000), 읽기 전용 모드 플래그.
- 어댑터 계약 테스트(contract test)를 한 벌 작성해 세 구현이 같은 테스트를 통과하도록 함.

수용 기준
- Oxigraph와 Fuseki(Docker)에 같은 계약 테스트가 통과한다.
- Knowledge Studio 연동 시 확인할 질문 목록이 문서화되어 있다.

### M04. 온톨로지 탐색·시각화
**목적** 비전문가도 개념·관계를 이해하고, 전문가는 원본을 본다.

핵심 요구사항
- 클래스 계층 트리(좌측), 그래프 캔버스(중앙, Cytoscape.js), 상세 패널(우측: 레이블 ko/en, 정의, 속성, 인스턴스 수, 품질 이슈, 이 개념이 쓰인 질의 수).
- 그래프 모드: 스키마 뷰(클래스-속성-클래스), 인스턴스 이웃 뷰(선택 인스턴스의 N-hop), 경로 탐색(두 개념 사이 경로).
- 성능: 클래스 500개, 엣지 2,000개까지 60fps 근접. 그 이상은 클러스터링·포커스 모드.
- 검색: 레이블·IRI·정의 전문 검색, ⌘K 팔레트 통합.
- 전문가 서랍: 선택 요소의 Turtle 스니펫 표시·복사, 편집은 P1(M12)에서.
- 내보내기: PNG/SVG, 현재 뷰의 Turtle.

수용 기준
- 샘플 도메인 로드 후 3초 이내 첫 렌더.
- 트리·캔버스·패널 선택 상태가 동기화된다.
- 키보드만으로 개념 검색→선택→이웃 확장이 가능하다.

### M05. NL2SPARQL 질의 콘솔 (데모 수준)
**목적** "질문하면 답이 나온다"를 체험시키고, 질의 건수를 과금 단위로 만든다.

핵심 요구사항
- 파이프라인: 질문 → 스키마 컨텍스트 선택(질문과 관련된 클래스·속성만 임베딩 유사도 또는 키워드로 추출) → LLM이 SPARQL 생성(구조화 출력: `sparql`, `explanation_ko`, `explanation_en`, `confidence`, `used_terms[]`) → 정적 검증(파싱, 사용된 IRI가 온톨로지에 존재) → 실행 → 결과.
- 실패 시 최대 2회 자기 수정(오류 메시지 피드백). 그래도 실패하면 "이렇게 물어보세요" 유사 샘플 질문 제안.
- UI: 질문 입력(한/영), 생성된 SPARQL 미리보기(편집 가능, 전문가 서랍), 결과 표 + 결과 그래프(결과 인스턴스를 M04 캔버스에 하이라이트), 신뢰도 배지, "이 답이 맞나요?" 👍👎 피드백.
- 질의 이력과 즐겨찾기. 즐겨찾기는 "저장된 질문"으로 대시보드 위젯화 가능(P1).
- LLM 호출은 `LLMGateway` 경유. 기본 모델 `claude-opus-5`(품질), 라우트 설정으로 `claude-sonnet-5`(비용) 전환 가능. 구조화 출력 사용, 스키마 컨텍스트에 프롬프트 캐싱 적용.
- 골든셋 12문항 자동 평가 스크립트(정확 일치가 아니라 결과 집합 일치로 채점).

수용 기준
- 골든셋 12문항 중 9문항 이상 결과 일치.
- 평균 응답 4초 이내(캐시 적중 시).
- 모든 질의가 미터링 이벤트(`nl_query`, 토큰·비용 포함)로 기록된다.

### M06. 온톨로지 품질 리포트 (데모 수준)
**목적** "우리 온톨로지가 어디가 약한지"를 점수와 목록으로 즉시 보여준다.

핵심 요구사항
- 규칙 기반 지표(결정적, LLM 불필요):
  - 구조: 고아 클래스, 순환 subClassOf, 도메인/레인지 누락 속성, 미사용 클래스·속성(인스턴스 0), 다중 상속 과다
  - 문서화: rdfs:label 누락(언어별), rdfs:comment 누락, 정의 길이 부족
  - 영문화: 영문 레이블 커버리지(%), 한/영 레이블 불일치 의심(번역 검사는 LLM 옵션)
  - 명명: 클래스 PascalCase, 속성 camelCase, IRI 규칙 위반
  - 데이터: 레인지 위반 인스턴스 수, 필수 속성 누락 인스턴스 비율
- 점수 카드: 총점 0~100 = 구조 40 + 문서화 30 + 영문화 15 + 명명 15 (가중치 설정 가능). 등급 A~E. 이전 실행 대비 변화.
- LLM 요약(옵션, 과금): 상위 이슈 5개를 자연어로 설명하고 수정 제안(Turtle 패치 초안). 적용은 P1(M12)에서.
- 이슈 목록에서 클릭하면 M04 캔버스에서 해당 요소로 이동.
- 리포트 내보내기: PDF/Markdown(ko/en).

수용 기준
- 샘플 도메인의 의도된 결함을 100% 검출, 오탐 0.
- 클래스 1,000개 온톨로지에서 10초 이내 실행.
- 점수 산식이 `02-roi-model.md`의 "리스크 절감" 지표와 연결된다(품질 점수 상승 → 리스크 절감 추정).

### M07. ROI 계산기·가치 대시보드
**목적** 고객이 자기 숫자를 넣으면 비용·효익·ROI·회수 기간이 즉시 보이고, 사용할수록 실측치로 대체된다. 산식은 `02-roi-model.md`.

핵심 요구사항
- 입력 위저드 8문항(기업 규모, 데이터 관련 인력 수, 평균 인건비, 주당 데이터 탐색 시간, 월간 분석 산출물 수, 데이터 사고 빈도·비용, 연간 통합 프로젝트 수, 고객 수·이탈률). 모든 항목에 기본값·업계 범위·출처 툴팁.
- 효익 5분류 각각 카드로 표시: 직접비 절감, 사이클 타임 향상, 고객만족, 리스크 절감, 추가비용 회피. 카드마다 "가정" 또는 "실측" 배지.
- 비용 측: 선택 플랜 기본료 + 예상 데이터 규모·사용량 종량 + 도입 인력 시간 + 변경관리. 플랜 변경 시 즉시 재계산.
- 산출: 연간 순효익, ROI(%), 회수 기간(개월), 3년 NPV(할인율 설정). 보수·기본·낙관 3시나리오 토글(효익 실현율 50/75/100%).
- 실측 연동: NL 질의 수 × 질의당 절감 분, 품질 점수 변화, 문서 생성 건수를 미터링에서 읽어 "실측" 값으로 대체.
- 공유: 읽기 전용 링크와 PDF(ko/en). 경영진 보고용 한 장 요약 레이아웃.
- 모든 산식은 백엔드 순수 함수로 구현하고 단위 테스트. 프론트는 표시만.

수용 기준
- 기본값만으로 60초 안에 결과 화면 도달.
- 산식 단위 테스트가 `02-roi-model.md`의 예시 수치와 일치.
- PDF 내보내기가 한/영 모두 깨지지 않는다.

### M08. 미터링·플랜·한도 (컷 가능)
**목적** 과금의 기초 데이터를 처음부터 쌓는다. 실제 결제는 P1.

핵심 요구사항
- 이벤트 스키마: `{workspace_id, event_type, quantity, unit, cost_krw, llm_tokens_in/out, model, created_at, ref_id}`. 타입: `nl_query`, `llm_generation`, `quality_run`, `doc_generation`, `api_call`, `triple_snapshot`(일 1회 트리플·클래스 수).
- 플랜 정의 파일(YAML): Trial / Team / Enterprise 한도와 단가. `02-roi-model.md` 가격표와 동일.
- 한도 도달 시 소프트 블록(경고 배너 → 업그레이드 CTA), 트라이얼은 하드 블록.
- 사용량 화면: 이번 달 사용량·예상 청구액·플랜 대비 비율. 이 화면이 ROI 대시보드의 "비용" 실측치.
- 미터링 실패가 사용자 요청을 실패시키지 않도록 비동기 큐(Redis)로 기록.

### M09. i18n
**목적** UI와 온톨로지 모두 한/영을 1급으로 지원한다.

핵심 요구사항
- UI: next-intl, 기본 ko, 브라우저 언어 감지, 사용자 설정 우선. 모든 문자열 키 기반. 누락 키 CI 검사.
- 온톨로지: rdfs:label/comment의 `@ko`, `@en` 병행 표시. 우선 언어 설정.
- 영문 자동 번역 제안: 영문 레이블 누락 항목을 LLM으로 일괄 제안(도메인 용어집 컨텍스트 주입), 검토 후 적용. 과금 이벤트 `llm_generation`.
- 문서·리포트·PDF 모두 ko/en 생성.

### M10. 문서 자동 생성 (컷 가능)
**목적** 온톨로지에서 데이터 사전과 개념 문서를 자동 생성해 문서화 부담을 없앤다.

핵심 요구사항
- 온톨로지 → 정적 문서 사이트(Markdown/HTML): 개요, 클래스별 페이지(정의, 상위·하위, 속성, 예시 인스턴스, 다이어그램 SVG), 속성 색인, 용어집(ko/en).
- LLM 옵션: 정의가 없는 개념에 대한 정의 초안, 개념 간 관계 설명 문단. 과금 이벤트.
- 내보내기: ZIP(HTML), 단일 PDF, Confluence/Notion 붙여넣기용 Markdown.
- 생성 문서는 버전 태그와 생성 시각을 표기.

## P1 모듈 요약 요구사항

- **M11 온톨로지 초안 자동 생성**: 업로드(PDF/DOCX/XLSX/DB 스키마 DDL) → 용어 추출 → 클래스·속성 후보 → 검토 UI(승인/병합/삭제) → Turtle 생성 → M06 품질 검사 자동 실행. 생성 과정을 단계별로 보여주고 각 후보에 근거 문장 링크.
- **M12 변경관리·버전·승인**: 모든 편집은 제안(Proposal)으로 시작 → diff(Turtle·시각) → 검토자 승인 → 배포. 배포마다 버전 태그, 롤백, 변경 로그 자동 문서화(M10 연동). 이것이 "운영 단계 고객 셀프 업데이트"의 핵심.
- **M13 데이터 커넥터·매핑**: CSV/Excel/PostgreSQL/MySQL 연결 → 컬럼-속성 매핑 제안(LLM) → RML 생성 → 스케줄 적재. 트리플 규모가 늘어 종량 매출로 연결.
- **M14 결제·청구**: Stripe(해외) 또는 토스페이먼츠(국내) 어댑터. 월 청구서 = 기본료 + M08 종량. 인보이스 PDF, 세금계산서 연동은 P2.
- **M15 API 키·SDK·웹훅**: 워크스페이스별 키, SPARQL·NL 질의 REST 엔드포인트, TypeScript/Python SDK, 온톨로지 변경 웹훅. API 호출 종량.
- **M16 금융 샘플 도메인**: 금융상품·규제 조항·리스크 요인·고객 세그먼트. 규제 준수 질의 골든셋.
- **M17 내부 관리자 콘솔**: 테넌트 목록, 가입 퍼널(가입→샘플→첫 질의→ROI 조회→업그레이드 클릭), 사용량 상위 고객, LLM 비용 대비 매출.
